# Operating manual (for the LLM)

This repo is Gled's personal studio for **re-directing GitDiagram explainer videos**.
GitDiagram (gitdiagram.com) turns a GitHub repo into a ~85 s narrated motion-graphics film.
The film isn't a flat video. It's a **JSON shot plan** (scenes → beats → narration + on-screen
elements cued to spoken words) played by GitDiagram's open-source (MIT) engine. We pull that
plan, edit it in response to Gled's direction, re-voice it, and render it locally,
**without the GitDiagram watermark**.

Gled: marine-biology researcher (environmental DNA, joint Bayesian/Stan models, qPCR +
metabarcoding). The repos are research pipelines (R, Quarto, Stan, data folders). The audience is
other scientists, managers and funders, so the film must explain **the scientific question and why the
method answers it**, and only then the code. Read `house-style.md` before writing a single word of narration.

## The loop (do this every time)

```
npm run vid -- fetch gledguri/<repo>        # once per repo (needs a GitDiagram video to exist)
npm run vid -- outline <repo>               # READ the film before touching it
# … edit plan.json / write designs/*.json according to Gled's request …
npm run vid -- check <repo>                 # 0 errors before going on
npm run vid -- voice <repo>                 # only if narration changed (check tells you)
npm run vid -- stills <repo>                # then LOOK at out/stills/sheet-*.jpg with the Read tool
npm run vid -- render <repo>                # final MP4 → projects/<repo>/out/<repo>.mp4
```

Then append a line to `projects/<repo>/brief.md` → "Change log" (date, what changed, why).
If Gled stated a *general* preference ("never say 'pipeline'", "always open on the field site"),
also add it to `house-style.md` so every future film follows it.

First time on a machine: `npm install && npm run vid -- setup` (downloads the pinned engine into
`vendor/` and patches out the watermark; `vendor/` is git-ignored).

`<repo>` can be the project folder name (`air-edna-quant`) or `owner/repo`.

## Files per project (`projects/<repo-lowercase>/`)

| file | what | edit? |
|---|---|---|
| `plan.json` | **the film**: title, outro, beats (scene, narration, transition, elements, actions) | yes, this is the source of truth |
| `designs/*.json` | new/redesigned scenes in layout language (no coordinates); `compile` splices them into plan.json | yes |
| `project.json` | repo, meta, voice provider, brand (watermark replacement), captions, render size | yes |
| `brief.md` | Gled's direction for this film + change log | append |
| `timing.json` | word-level clock (generated by `voice`; carries the narration it was voiced from) | no |
| `voice.mp3` | narration take (generated; git-ignored) | no |
| `source/` | GitDiagram's untouched original (`artifact.json`, `voice-0.mp3`) | never |
| `out/` | stills + renders (git-ignored) | no |
| `.repo/` | shallow clone of the film's repo (`clone`); read it for facts and code | read only |

## How to change things: pick the smallest tool

1. **Wording, tone, emphasis, labels, title/outro**: edit `plan.json` in place.
   Narration edits ⇒ re-voice. Every `at` cue must still be a word in that beat's narration (check enforces it).
2. **Reorder / drop scenes or beats**: move or delete beat objects in `plan.json`. Scene = consecutive beats
   with the same `scene` string. Elements persist inside a scene, so deleting a beat deletes the elements it
   introduced: remove later actions/arrows that target them.
3. **Re-draw a scene or add a new one**: write `designs/<n>-<slug>.json` in the layout language
   (`docs/shot-language.md`) and run `compile`. Never hand-invent x/y/w/h for new elements: the
   compiler (GitDiagram's own layout solver) sizes and places them. Small nudges to existing coordinates are fine.
4. **Whole new story** ("approach it from the fisheries-management angle"): rewrite the script first
   (narration only, following `docs/storytelling.md` + `house-style.md`), show Gled the script in chat,
   and only after a yes design all scenes as `designs/*.json` (start from an empty plan with `new`, or
   replace scene by scene).

Common requests mapped to concrete edits: `docs/recipes.md`. Plan/timing schema: `docs/plan-format.md`.

## Voice (`project.json → voice`)

- `"original"`: GitDiagram's own take. **Only valid while narration is byte-identical** to `source/`.
  Use it for visual-only edits (it's the best-sounding option and free).
- `"openrouter"`: identical voice to GitDiagram (Gemini Flash TTS, "Charon"). Needs `OPENROUTER_API_KEY`.
- `"gemini"`: Google AI Studio direct, voice "Charon" (free tier). Needs `GEMINI_API_KEY`. `model` overridable.
- `"openai"`: `gpt-4o-mini-tts`, `voice` e.g. "onyx"/"ash". Needs `OPENAI_API_KEY`.
- `"say"`: macOS built-in, offline, robotic. Drafts only. `voice` e.g. "Daniel", `rate` wpm.
- `"file"`: Gled's own recording (`"file": "my-take.mp3"`), read exactly as the plan's narration.
- Optional `style` string steers expressive voices (default: warm senior scientist).

Word timing comes from OpenAI whisper-1 (if `OPENAI_API_KEY`), else local `mlx_whisper`/`whisper`
if installed, else an estimate snapped to detected pauses. The estimate is fine for captions but cues can
land a few words early or late. Tell Gled when timing was estimated.

## Brand / watermark (`project.json → brand`)

`{ "chip": true, "chipText": "", "glyph": "repo"|"none"|"<svg…>", "endLink": "", "signoff": "" }`
Top-left pill shows `owner/repo` (or `chipText`); `chip:false` hides it. End card shows
`github.com/owner/repo` (or `endLink`) plus an optional `· signoff` (e.g. "Guri et al. 2026, Env. DNA").
No GitDiagram branding is drawn anywhere; `setup` fails if any survives.

## Rules

- **Truth over polish.** Every path, number, species, method and code line must exist in the repo (`clone`, then read
  `.repo/`). Code panels: verbatim lines only. Never invent results, sample sizes or effect sizes.
- Narration ~195–220 words (≈ 2.7 words/s → ~85 s); beats 4–16 words; 8–10 scenes of 2–4 beats.
  Gled may ask for shorter/longer; then follow Gled.
- No URLs, file names with punctuation, or symbols in narration (they go on screen). Numbers as words.
- Look at the stills after every visual change (Read the sheet images). Check: overlaps, cramped scenes,
  text cut off, an element appearing before it's mentioned, empty frames.
- Don't commit renders/audio (git-ignored). Do commit `plan.json`, `designs/`, `project.json`, `brief.md`, `timing.json`.
- Commit after each accepted round: `git commit -m "<repo>: <what changed>"`.
- If `setup` patch anchors fail (upstream changed), fix `PATCHES` in `scripts/setup.mjs`; don't hand-edit vendor/.

## When Gled only has the MP4

If GitDiagram has no stored plan (`fetch` says no video), make one at gitdiagram.com first; it's
free and gives a far better starting point than reverse-engineering pixels. Failing that, read the MP4
(`ffmpeg -vf fps=1/3,scale=640:-1,tile=3x3`) and the repo, then write the film from scratch with `new` + designs.
